# Phase 2 proposal — no accounting changes implemented

Owner policy is authoritative: GST-inclusive eligible issued invoice sales, independent of payment receipt; drafts/cancellations/voids excluded; canonical invoice counted once; valid linked sales credit/reversal adjustments; stable employee attribution; verified invoice issue date. Phase 1 changes only monthly percentage rounding. Every proposal below requires reconciliation review and explicit approval before implementation.

## Review and release gates

1. Phase 1 rounding tests/build pass and its small frontend delta is reviewed independently. This is not financial deployment approval.
2. Obtain approved SELECT-only source; verify actual schema/status vocabulary/adjustment model and aggregate all period/scope exceptions. Quantify a non-overlapping waterfall from legacy to owner-policy totals. Keep customer names, employee names, document identifiers, addresses and credentials out of exported reports.
3. Owner/accountant reviews status mapping, salesperson exceptions, adjustments, date/closed-period rules and gross-basis differences. Record all approvals and baseline aggregates.
4. Propose a coherent, versioned reporting change for monthly/yearly cards and dependent reports/charts. Show both legacy and proposed totals in a private review artifact, not an unapproved production UI.
5. Run shared financial contract tests plus backend/security and light/dark responsive regression checks. Assert no payment receipt becomes extra sales and no canonical invoice or adjustment is counted twice.
6. Only after explicit approval, implement/deploy the approved scope with a rollback/versioning plan and post-deployment read-only reconciliation. Do not rewrite underlying historical records as a side effect of reporting.

No Phase 2 production logic, migration, backfill, cancellation handling, employee remapping, adjustment netting, timezone regrouping or yearly calculation change has been implemented.
